# 为什么生产环境不能用 python app.py？
因为 Flask 自带服务器不具备生产级并发能力和稳定性

# 请求为什么要先到 Nginx，而不是直接到 Flask？
因为 Flask 不适合直接对外提供服务，需要 Nginx 做流量入口和保护层

# Gunicorn 和 Flask 的关系是什么？
Flask 是应用，Gunicorn 是运行它的服务器, 是并发控制器 + 进程管理器

# gunicorn app:app 中两个 app 分别代表什么？ 
第一个是模块名（文件名去掉.py） 第二个是Flask应用对象

# 为什么 Gunicorn 可以提高并发能力？
每个进程可以同时处理请求 → 提高并发能力

# 如果我把 gunicorn -w 4 -b 127.0.0.1:5000 day13.app:app 中的 -w 4 改成 -w 1 会发生什么？
只有1个worker（单进程）并发能力低 请求阻塞多，容易卡住

# Nginx 为什么不直接处理业务，而要转发给 Gunicorn？
Nginx 是门卫，Gunicorn + Flask 是员工

# Gunicorn（应用服务器）和 Nginx（反向代理）都部署后，如果用户访问 localhost，请求是如何一步一步流转的？
浏览器 → Nginx（80端口接收请求）→ Gunicorn（5000端口）→ Flask（处理业务）→ 返回数据（原路返回）

# 如果 Gunicorn 挂了，Nginx 会发生什么现象？
502 Bad Gateway 意思就是后端服务器挂了

# WSL(Linux)中数据库配置proxy_pass http://127.0.0.1:5000/; 👉 最后这个 / 很重要！为什么？
✔ 有 /
/api/users → /users
❌ 没 /
/api/users → /api/users

# 为什么静态资源不走 Flask，而交给 Nginx？
因为 Nginx 处理静态资源更高效,为了性能

# api/users 到 Flask 后，路径为什么变成 /users？
因为在 Nginx 配置中做了路径转发（rewrite/代理规则）

# 如果访问 /login（没有 /api），会发生什么？
没有 /api 的请求，一般不会进 Flask，而是被 Nginx 当静态资源处理

# 为什么必须用云服务器，而不是一直用自己电脑？
因为云服务器具备公网访问能力，可以让外部用户随时访问项目，而本地电脑通常没有公网IP且不稳定，无法提供持续服务。

# 如果你没有开放80端口，会发生什么？
请求会被服务器防火墙/安全组拦截，外部无法建立连接，因此浏览器无法访问服务。
本质是TCP连接建立失败

# 项目上线云服务器后，用户访问你的网站，请求完整链路是怎样的？
浏览器 →（DNS解析IP）→ 云服务器公网IP → Nginx（80端口接收请求）→ 转发到 Gunicorn（5000端口）
→ Flask处理业务 → 查询数据库（MySQL）→ 返回结果 → Nginx → 浏览器（原路返回）

# 为什么不能直接用 gunicorn 命令一直跑，而要用 systemd？
Gunicorn直接运行不具备守护能力，而 systemd 提供后台运行、自动重启、开机自启等生产级能力

# Restart=always 的作用是什么？
进程挂掉自动拉起（自愈能力） 重启

# 如果服务器重启了，你的服务为什么还能自动运行？
因为设置了服务器开机服务就启动（开机自启）
systemd + enable → 注册为系统服务 → 开机自动启动
