# 一、什么是 JWT
JWT是基于token的认证方式， 服务器在登录时生成token返回给客户端， token中包含用户信息和过期时间。

客户端在后续请求中携带token， 服务器通过验证token的合法性和有效期来识别用户， 从而实现无状态认证。

# 自定义异常 = 必须调用父类 Exception 初始化，否则异常信息不会被正确存储

# 问: 用户认证和JWT完成后，现在登录后服务器为什么不需要保存登录状态？
答: 因为 JWT 是无状态认证机制,是“自包含”的（self-contained）。

登录成功后，服务器生成 token 返回给客户端， token 中包含用户信息，并通过签名保证不被篡改。

客户端后续请求携带 token， 服务器只需验证 token 的合法性即可识别用户， 不需要在服务器端保存任何登录状态。

# 👉 为什么 password 要用 255？
因为密码是经过哈希加密存储的，生成的字符串长度较长，
通常需要预留 255 字符来兼容不同加密算法（如 bcrypt、scrypt）。

# 👉 JWT 怎么实现退出登录？
JWT 本身是无状态的，服务器无法主动让 token 失效。

常见解决方案有：
1. 前端删除 token（基础方案）
2. 设置过期时间（exp）
3. 使用黑名单机制（如 Redis 存储失效 token）
4. 使用 token 版本号机制，使旧 token 失效

# JWT 退出登录用哪种方案更好？
我更倾向于使用短过期时间 + refresh token 的方式。

因为 JWT 的设计初衷是无状态，
如果使用黑名单机制，会引入额外的存储（如 Redis），
违背了无状态的优势，同时会增加系统复杂度和存储压力。

而短期 token（如15分钟）即使泄露，风险窗口也较小，
配合 refresh token 可以实现用户无感续期，
在安全性和性能之间取得更好的平衡。

# 你使用Access Token（15分钟）, Refresh Token（7天）👉如果 Refresh Token 被盗了怎么办？
如果 Refresh Token 被盗，攻击者可以持续获取新的 Access Token。

解决方案是：
1. 将 Refresh Token 存储在服务端（如 Redis），支持主动失效
2. 使用 Refresh Token 轮换机制，每次刷新都会生成新的 token，并使旧 token 失效
3. 可结合设备信息进行校验，提高安全性

这样可以在保证用户体验的同时，降低 token 被盗带来的风险。

# 为什么要分页？（面试必问🔥） 分页本质是什么？
数据太多（10万条）一次返回会卡死 浪费带宽 前端也处理不了
本质原理: 分页 = LIMIT + OFFSET
SQL本质是：
SELECT * FROM users
LIMIT size OFFSET (page-1)*size;

# 为什么我们要用“装饰器”来做权限控制，而不是把判断写在每个接口里？
用装饰器做权限控制 = 解耦 + 复用 + 统一管理
答：
使用装饰器可以将权限控制逻辑与业务逻辑解耦，
避免重复代码，提高代码复用性和可维护性，
同时可以统一管理权限校验，防止遗漏，提升系统安全性。
