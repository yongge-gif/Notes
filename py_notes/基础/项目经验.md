# 安全性问题（用户枚举）& 什么叫用户枚举？
如果接口返回：

用户不存在
{
  "msg": "账号错误"
}

密码错误
{
  "msg": "密码错误"
}

攻击者就能知道： 这个用户名真实存在
🚀 黑客可以批量试： admin root test manager 
然后根据： 账号错误 / 密码错误 判断： 哪些用户真实存在
这就是： 用户枚举漏洞(User Enumeration)

# bcrypt 密码长度限制问题导致注册用户失败报错
ValueError: password cannot be longer than 72 bytes, truncate manually if necessary (e.g. my_password[:72])
原因: bcrypt 5.0.0 修改了： 超长密码处理逻辑
以前： 超长可能： 自动截断
现在： 直接抛异常： ValueError
而： Passlib 某些版本内部兼容没完全跟上。
🚀 所以很多 FastAPI 项目都会固定：
bcrypt==4.0.1

# 更新头像失败
报错: UnicodeDecodeError: 'utf-8' codec can't decode byte 0x89 in position 216: invalid start byte
原因: 你上传图片时： 请求实际上打到了： PUT /users/{user_id} 这个接口。 不是： PUT /users/avatar
🧠 为什么？  **动态路由吞静态路由**
因为 FastAPI 路由匹配： /users/{user_id} 会把： avatar 当成： user_id = "avatar"于是： user_id: int 校验失败。
FastAPI 尝试返回错误详情时： multipart/form-data 里面有图片二进制 然后： o.decode()炸了。
解决方案（核心）
@router.put("/users/{user_id}")接口： 必须放到 @router.put("/users/avatar")后面。
🚨 FastAPI 路由顺序很重要
